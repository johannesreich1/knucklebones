Each was picked in isolation, so nothing lines up between screens and the ladder ended up visibly wider than everything else.
Shipped — three tokens
--w-app: 520px--w-col: 400px--pad-x: 14px
the shell (tablet / desktop cap)
--w-app
every screen body
--w-col
One column. Forms, lists, cards, headers and action stacks are all --w-col and no wider, so nothing has to be kept in sync with anything else. On a phone the padding wins and it fills the screen; on a tablet it stops at 400 instead of stretching into an unreadable line.
Capping the column was not enough on its own: the INSET differed too (26px on overlays, 14px inside scroll views), so the same cap produced 388 / 400 / 372 on three screens. --pad-x decides how close content comes to the glass, --w-col decides how wide it may get. Measured after: home, profile, mode cards, rules, ladder rows and both headers all 400.
What it changed
Home 300 → 400: the menu stopped floating in the middle of a wide screen.
Profile 340 → 400: the identity block and stats got the same room.
Ladder edge-to-edge → 400: no longer the odd one out.
Mode cards 376 → 400, rules 360 → 400, headers 340 → 400 — so the ✕ sits directly above the content it closes.
The board 430 → --w-col: fit() reads the token, so the playfield stops where the menus do instead of being wider than its own UI.
Deliberate exceptions (NOT columns)
.land #coach 300 — a floating bubble, not a page body.
.land .status 104 — a wrap width for two words.
.focard 356 — the face-off, a modal card over the ladder, not a page body.
.focol .fnm 130 — an ellipsis width for a nickname beside VS.
.lrow .nm / .lb .row .nm — nickname ellipsis needs no width at all: min-width:0 on the flex parent does it. (It was .awho .meta until the profile became the ring + plate; that selector styles nothing now.)
These stay literal; where the reason is not obvious the comment says why. A token would imply they move together with the column; they do not.
