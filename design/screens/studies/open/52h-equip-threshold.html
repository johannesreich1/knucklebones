What it says: SILVER is a moment, not a number. The match that carries you over 1,260 deals one more card — the group as kicker, your rune in its own hue, and the news that it now comes with you. Before the crossing the profile says chosen-and-waiting through the frosted bar offline setup already uses for your choice does not apply here; after it nothing needs saying, because the rune is in play. The card is drawn twice here on purpose: once as EQ8 asks for it, dashed, and once inside the spec the result screen actually has.
Why it survives: it announces rune news where the app already announces rune news. #endFeature is a typed slot with a shipped skin, grid and rise, so this is one more caller and not one more screen. And it got cheaper this week. d42b869 made the reward card a door: its tap is now openEntry('spells', id) — the same sheet the in-game badge opens, the same sheet the profile collection opens, the same sheet EQ4's ring seat opens. One sheet, four ways in, which is the strongest evidence on this board that "the mark is a door" is the app's existing grammar rather than a new idea. The threshold news fits that shape without asking for anything: kicker SILVER, name WARD, chevron, and the "comes with you into every ranked match" line supplied as the sheet's .mcmeta through the presentation() override account-runes.ts already uses for a locked rune. That variant is drawn above, tagged ships today, and it is the one this study would actually ship.
Cost, and it went up: the hero card is no longer a small extension of EndFeature — it is a disagreement with it. Two commits ago d42b869 deleted the blurb and the CTA from this exact row, on the reasoning that a printed explanation is a second copy of the sheet's own text and a button beside a tappable card is two targets for one destination. The interface is now { className, hue, icon, kicker, title, tap } (endscreen.ts:26) with no body and no action, and #endFeature is the <button type="button"> (markup.ts:330), which a second button cannot legally sit inside. So Change and its line cost a reopened decision, a re-typed spec and a rebuilt element, not a stylesheet — and the same holds for CHOOSE A RUNE and NO RUNE YET, which is why all three are drawn dashed. The slot arithmetic is unchanged and still bites: at 1,170 the player is IVORY, which is where Rune Ritual is dealt, so the same +90 that lands him on SILVER can also be the win that grants a rune he did not own. One card must lose the single slot and be re-presented later, so the threshold needs its own durable seen_at row beside player_runes: a migration, not a stylesheet. And the largest cost is still that a promotion fires once — equip a week after crossing and this card never deals at all, which is why the quiet profile reading is drawn here full size and carries more of the design than the event it is named for.
The state easiest to get wrong: Rune Ritual. The threshold card never deals after a Ritual result — that result already owns the slot — and the profile ring does not move, because the server's three-rune loan was never an equip. docs/SPELLS.md is explicit that an equipped rune is ignored there and never overwritten, and a ring that flickered for one match would be the first thing to break that promise. Same answer for a demotion: the ring stays, the bar comes back.
